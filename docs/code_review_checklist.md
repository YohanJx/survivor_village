# 代码评审与交付检查表

本表是 [完整规范](project_conventions.md) 的执行入口。本轮已填写的门禁与证据见 [整改验收记录](validation_report.md)。逐项填写“通过 / 不适用及理由 / 未通过”；没有证据的项目不能标记通过。只检查本次范围及其直接依赖，但不能用范围小为由掩盖已知阻断问题。

## 开工前

- [ ] 已读 `AGENTS.md`、完整规范和相关代码，说明本次要解决的具体行为。
- [ ] 已确认状态所有者、输入输出、失败行为、涉及的资源与存档兼容性。
- [ ] 改动是完整的纵向切片：定义 → 规则 → 调用方 → 测试 → 文档；没有新旧接口混用。
- [ ] 新抽象有真实需求，未重复建立现有模型、万能管理器或全局事件总线。

## 代码与依赖

- [ ] 显式类型、类型化容器、命名、私有接口、函数顺序及两空行符合规范。
- [ ] 卡牌/建筑用原生 Resource；封闭玩法状态用枚举；稳定配置 ID 仅用于索引、存档和边界。
- [ ] UI 只展示和发起请求；规则不查找场景节点；模拟器不操作 UI。
- [ ] 新增长期静态 UI 布局使用可编辑场景；复杂组件有独立职责，不继续扩大入口脚本。
- [ ] 共享定义只读；运行时状态和嵌套快照有明确复制策略。
- [ ] 没有忽略错误、关闭警告、空异常处理或以动态类型绕过错误。
- [ ] 超过规模审查阈值的函数/脚本有职责拆分或书面理由。

## 规则与状态

- [ ] 费用先汇总验证，失败没有部分扣费、部分建造、时间推进或信号副作用。
- [ ] 前置、等级上限、条件效果与预览使用同一规则，未知效果/配置显式报错。
- [ ] 阶段转换验证来源阶段；重复入夜、战报、奖励与黎明请求不会重复执行。
- [ ] 加法、乘法、钳制顺序及同优先级联动顺序确定，结果不依赖偶然遍历顺序。
- [ ] 黄昏快照、电力只扣一次、临时效果到期、存活人口消耗和缺粮惩罚有覆盖。
- [ ] 信号在完整提交后发送；回调不会在同一事务中再次执行原操作。

## 存档与资源

- [ ] 库中 ID 唯一，资源引用有效，枚举数值与数组长度一致，嵌套配置校验完整。
- [ ] 读档先完整校验再提交，含有限数值、历史、战报、修正器、资源引用和阶段所需数据。
- [ ] 重读同一路径不会读取旧缓存；失败不修改当前局，也不覆盖有效旧档。
- [ ] 枚举/资源路径/字段变化已升级版本并说明迁移或拒绝策略。
- [ ] 测试使用独立存档，未覆盖玩家进度；不从不受信任的外部路径加载可执行资源。

## 运行与性能

- [ ] 固定模拟步长未被倍速改变；暂停期间不推进规则；随机数可重现。
- [ ] 热路径没有资源加载、场景树搜索、完整派生计算、频繁节点重建或无界分配。
- [ ] 导航变化、目标死亡、相邻单位死亡和战斗结束都有一致处理。
- [ ] 性能改动附相同场景/种子/硬件的前后记录；未凭 if 数量宣称优化成功。
- [ ] UI 实际检查过选择、禁用、快捷键、重复输入、奖励、暂停/倍速、缩放与中文。
